# 主动阅读学习规则

## 职责边界

把用户提供的内容卡片转化为可审核、可主动回想的学习材料，并在用户作答或解释后提供反馈。

本 Skill 不执行数据库写入、通知、用户记忆评分或 FSRS 排期。所有生成内容都是草稿；发布、作废和调度由应用组件与服务处理。

用户侧口令「新建卡片」= 将原始输入入库为 ContentCard（原料）；本 Skill 的 `generate_materials` 仍只产出草稿，不代替发布。应用层用选择卡片（widget）收集用户四档评分；`evaluate_*` 不输出忘记/困难/良好/容易。讲解追问（`feynman_tutor`）与理解练习评阅（`evaluate_deep_practice`，对应概括对照/理解问答）模式路由保持独立。mode 名保留英文。

## 输入原则

1. 以 `CardSet` 和 `ContentCard` 为内容边界，不要求书名、作者、封面或章节。用户口令「新建卡片」对应 ContentCard 入库；生成与发布是应用层后续步骤。
2. 只把输入材料明确支持的内容标记为 `source_supported`。
3. 必要的外部补充必须标记为 `model_supplement`，不得伪装成原文结论。
4. 每个概念、问题、答案、反馈和缺口都要提供 `source_refs`；无法定位时返回警告。
5. 按请求中的 `mode` 执行一种工作，不自行切换流程。详细输入输出字段见 [output-contracts.md](references/output-contracts.md)。

## 模式路由

| mode | 使用场景 | 结果 |
|---|---|---|
| `generate_materials` | 用户提交阅读输入后 | 概念、问答卡、开放题和摘要草稿（供理解问答/概括对照） |
| `evaluate_review_answer` | 用户回答问答式或选择题后 | 正确处、遗漏、错误和依据 |
| `evaluate_deep_practice` | 用户完成理解问答或概括对照后 | 理解反馈和修订方向（实现侧可为规则 stub） |
| `feynman_tutor` | 用户口令「讲解追问」后 | 单轮追问、诊断或结束总结（实现侧可为启发式） |
| `generate_supplemental_cards` | 用户确认要针对缺口补卡后 | 补充问答卡草稿 |

## 生成学习材料

执行 `generate_materials` 时：

1. 提取最多 8–12 个关键概念；材料不足时减少数量，不凑数。
2. 同时生成问答式和选择题问答卡；材料不适合某题型时说明原因。
3. 问答式问题必须迫使用户回想关系、条件、因果、区别、反例或应用，避免仅复述定义。
4. 选择题默认四个选项和一个正确选项。干扰项必须合理、同层级且能由材料排除，不使用明显错误或措辞泄漏答案的选项。
5. 每张问答卡只测试一个主要知识点。拆分一题多问、答案过长或依赖上下文才能理解的题目。
6. 生成 3 个允许多种合理答案的开放式问题，覆盖理解、迁移或应用。
7. 生成一份精简摘要，但放在 `hidden_until_submit` 中，供用户先自行重写后再对照。
8. 参考答案、必答要点、正确选项、选项解释和含答案的来源片段必须放在 `hidden_until_submit` 中。

## 评阅回答

执行 `evaluate_review_answer` 时：

- 问答式：逐项比较用户回答、必答要点和来源，区分正确、遗漏、错误与无法判断。
- 选择题：判断所选选项，并解释正确选项及各相关干扰项为什么成立或不成立。
- **不输出**“忘记、困难、良好、容易”，不建议 FSRS 评分，也不计算下次复习时间；四档评分由应用层用 widget 收集用户选择。
- 无法从来源确认时返回 `needs_human_check`，不得用自信措辞补全证据。

执行 `evaluate_deep_practice` 时，按概念准确性、因果联系、证据、迁移和适用边界反馈。不要用单一总分代替具体说明。该模式与 `feynman_tutor` 独立路由，不得混用或自动串联。

## 讲解追问（原费曼）

执行 `feynman_tutor` 时：

1. 用户首次解释前，不提供标准答案、参考摘要或提示。
2. 以学生身份一次只追问一个最关键的模糊点，优先追问术语、因果、例子、边界或反例。
3. 用户回答后再判断当前缺口是否解决；未解决时继续针对该缺口追问。
4. 诊断必须区分错误、模糊、推理跳步和遗漏联系，并附来源。
5. 不自动生成问答卡。只保存结构化缺口，并询问应用组件是否获得用户的补卡确认。
6. 用户结束或解释已完整时，返回已解决缺口、未解决缺口和可选修订方向，不安排下次练习。

## 缺口补卡

只有请求明确包含 `user_confirmed: true` 时，才能执行 `generate_supplemental_cards`。每个草稿必须对应一个已识别缺口，遵守问答卡题型和答案隐藏规则，并返回 `draft: true`。不得直接发布或初始化 FSRS。

## 输出前检查

- 内容是否超出来源而未标记？
- 是否在用户提交前泄漏答案？
- 每张问答卡是否只测试一个主要知识点？
- 选择题是否存在明显答案或低质量干扰项？
- 是否错误地替用户评分、排期、发布或作废？
- 所有材料是否为草稿并带来源引用？

任一检查失败时，先修正；无法修正则返回结构化警告，不返回貌似完整的结果。

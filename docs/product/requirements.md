# 功能需求

> **实现对齐说明**：下表以产品目标能力为主。当前参考实现（`<APP_HOME>/`，不在本仓）为单用户 SQLite MVP：生成/评阅/讲解追问多为启发式或规则 stub；无独立 Practice / Weakness / DeepPracticeSchedule / AIJob / ImportRecord / ReviewState 表；FSRS 字段落在 `review_cards`；内容卡片主要为 `body`。未实现项在验收列标「MVP 未做/简化」。无多租户鉴权、无默认通知、无微信读书导入。

## 1. 内容管理组件：卡片集与内容卡片

| 编号 | 优先级 | 功能 | 详细行为 | 验收标准 |
|---|---|---|---|---|
| R01 | P0 | 卡片集管理 | 新建、编辑、归档卡片集；名称、说明和标签均为通用字段 | 不要求作者、封面、ISBN 或其他书籍专属字段；归档后历史记录保留 |
| R02 | P0 | 内容卡片管理 | 在卡片集中创建内容卡片；每张内容卡片承载一段独立阅读输入；用户口令「新建卡片」对应本能力 | 内容卡片只要求正文，可来自网页、书籍、视频、课程或个人笔记；「新建卡片」入库后仍是原料，不自动成为可复习问答卡 |
| R03 | P0 | 材料录入 | 粘贴原文、划线、笔记、转录、链接或自己的理解；用户说法「新建卡片」即材料录入到指定卡片集 | 原始内容按输入版本原样保存，不限制来源规格；需再经「生成练习草稿」与「发布练习」才进复习队列 |
| R04 | P3 | 来源定位 | 可选记录 URL、页码、时间码、位置、小节或用户备注 | 未填写来源位置不影响内容卡片创建和问答卡生成 |
| R05 | P1 | 分段整理 | 将长材料拆成若干来源片段，并允许合并和调整 | 调整后不丢失原文及版本历史 |
| R06 | P1 | 标签与检索 | 按卡片集、内容卡片、概念、状态和自定义标签搜索 | 能从问答卡反查内容卡片，也能从内容卡片查看全部派生材料 |
| R07 | P1 | 内容版本 | 用户修改原文或笔记时保存版本 | 旧复习日志仍引用当时的材料版本 |
| R08 | P3 | 批量导入 | 导入 Markdown、纯文本或结构化笔记 | 导入前预览，失败项不影响成功项 |
| R09 | P2 | 微信读书笔记导入 | 读取用户授权可访问的微信读书划线与笔记；用户选择导入范围并预览映射结果 | 默认将所选书籍映射为卡片集、将划线或笔记映射为内容卡片；书名、作者、章节和位置仅作为可选来源信息；重复导入不创建重复内容 |
| R10 | P1 | 内容卡片失效与作废 | 用户可将内容卡片标记为失效或作废；失效可在修正后恢复，作废为终态 | 失效后停止生成新材料，派生问答卡进入来源失效待处理状态；作废前展示影响范围并由用户确认是否同时作废派生问答卡；两种状态都保留版本和历史记录 |

## 2. 材料生成组件

| 编号 | 优先级 | 功能 | 详细行为 | 验收标准 |
|---|---|---|---|---|
| G01 | P0 | 关键概念提取 | 从材料提取 8–12 个重要概念或论点；材料不足时减少数量 | 每项包含名称、解释和来源片段，不补造内容 |
| G02 | P0 | 问答卡生成 | 生成问答式和选择题两种问答卡；内容可覆盖事实、概念、因果、区别、条件、反例和应用 | 问答式要求用户主动组织答案；选择题包含选项和正确选项，不能仅靠明显干扰项猜中 |
| G03 | P0 | 隐藏答案与选项解释 | 问答式保存参考答案和必答要点；选择题保存选项、正确选项及各选项解释；两者都保存来源依据 | 用户提交前不返回参考答案、正确选项、解释或含答案的来源片段 |
| G04 | P0 | 理解问答草稿 | 每批生成 3 个理解、迁移或应用开放题（发布后供口令「理解问答」使用） | 允许多种合理答案；MVP 启发式生成，质量可经 draft-import |
| G05 | P0 | 参考摘要草稿 | 生成内容卡片精简摘要（供口令「概括对照」对照） | 默认隐藏，用户提交自写摘要后再展示；MVP 启发式 |
| G06 | P1 | 题型配比 | 根据材料性质分配问答式、选择题，以及记忆、理解和应用维度 | 不要求固定比例，但单批结果需说明采用的题型和认知维度 |
| G07 | P1 | 难度与粒度检查 | 检测一题多问、答案过长、问题含答案等问题 | 有问题的问答卡标为待修改，不直接进入复习 |
| G08 | P1 | 重复检测 | 对比同一卡片集已有概念和问答卡 | 重复内容提示合并、替换或保留，不自动删除 |
| G09 | P1 | 来源约束 | 生成内容区分“原文支持”和“Grok Bot 补充” | 无原文支持的推论必须显式标记 |
| G10 | P0 | 草稿审核 | 用户可编辑、拆分、删除、重新生成并确认 | 只有确认后的问答卡和练习进入正式队列 |
| G11 | P1 | 幂等生成 | 同一来源和请求 ID 重试时避免重复创建 | 网络重试不会生成两套相同草稿 |
| G12 | P1 | 生成失败恢复 | 保存输入和错误，可重试或手动创建问答卡 | Grok Bot 不可用时，已有材料与复习功能仍可使用 |

## 3. 问答卡复习组件

| 编号 | 优先级 | 功能 | 详细行为 | 验收标准 |
|---|---|---|---|---|
| A01 | P0 | 今日学习总览 | 分区显示“问答卡复习”和“理解练习”；理解练习区可分列概括对照 / 理解问答 / 讲解追问还剩数量 | 队列数量与实际数据一致；用户可只进入任意一条；MVP 见 `review.py today` |
| A02 | P0 | 仅显示问题 | 问答式显示问题和文本输入；选择题显示问题和选项；两种题型均可选择“想不起来” | 揭示前不泄漏参考答案、正确选项、解释或含答案原文 |
| A03 | P0 | 保存用户回答 | 问答式保存回答文本；选择题保存所选选项；同时保存开始时间、提交时间和提示使用情况 | 刷新或异常退出后可恢复 |
| A04 | P0 | 答案揭示 | 提交后，问答式展示参考答案和必答要点；选择题展示正确选项及选项解释；两者都展示来源 | 揭示事件写入复习日志 |
| A05 | P0 | Grok Bot 评价 | 问答式比较用户回答与要点；选择题解释所选选项为什么正确或错误 | 输出正确处、遗漏或错误；无法判断时明确标为“需人工核对” |
| A06 | P0 | 用户自评 | 提供忘记、困难、良好、容易四档评分 | 忘记表示未正确回想；困难仍是成功回想 |
| A07 | P0 | 间隔预览 | 显示四档评分各自预计下次复习时间 | 预览值来自当前 FSRS 状态 |
| A08 | P0 | 原子保存 | 同时保存评分、日志、新状态和到期日期 | 任一步失败则不推进问答卡状态 |
| A09 | P1 | 撤销评分 | 撤销上一张问答卡的最近一次评分 | 状态与日志均恢复到评分前 |
| A10 | P1 | 暂缓问答卡 | 将问答卡隐藏到下一学习日，不记为答错 | 暂缓不产生 FSRS 复习日志 |
| A11 | P1 | 暂停问答卡 | 无限期停止进入队列，用户手动恢复 | 历史记录和内容保留 |
| A12 | P1 | 同源问答卡避让 | 同一知识笔记派生的问答卡避免在同一时段相互提示 | 避让只改变展示，不改变记忆评分 |
| A13 | P1 | 问答卡编辑与版本 | 复习中可修正题型、问题、答案、选项或解释并记录版本 | 历史回答仍对应旧版本；重大改动可重置学习状态 |
| A14 | P0 | 会话控制与选集开场 | 开始今日复习**必须先指定卡片集**（不得无 set 开场）；列表展示「还剩 x/全部」（今日未学习数 / 未挂起活跃问答卡总数）；支持暂停、继续、结束 | 无卡片集不得开场；中途退出不丢失已完成评分；「还剩」口径与队列查询一致 |
| A15 | P2 | 快捷键 | 揭示、评分、编辑、暂缓支持键盘操作 | 快捷键不能跳过“先回答后揭示”的规则 |
| A16 | P1 | 理解练习建议 | 问答卡多次被评为“忘记”或“困难”时，提示用户是否进行讲解追问 | 只提供“现在开始、稍后安排、忽略”，不自动进入讲解追问；**MVP 未做**自动建议，仅支持用户显式口令启动 |
| A17 | P1 | 问答卡失效与作废 | 答案过时、题意不清或来源失效时可将问答卡标记为失效；修正并审核后可恢复；用户也可将其作废 | 失效和作废的问答卡立即退出复习队列；作废为终态，历史回答、评分和调度日志继续保留 |
| A18 | P0 | 会话结束语义 | 用户说「结束」→ 主动中止（SESSION_ABORTED），未评分卡不打分；队列暂时无可立刻出的卡 → 自然完成（SESSION_COMPLETE） | 两种结束状态可区分；中止不伪造评分、不推进未作答卡的 FSRS |
| A19 | P0 | 选择卡片 UI | 选择题选项与四档自评用选择卡片（widget）呈现；「想不起来」可用危险样式选项 | 仍遵守先答后揭示；评分仅由用户选择，Bot 不代评 |
| A20 | P0 | 学习中短间隔不默认推送 | 学习中（learning）短间隔卡在本场自然结束后仍保留 due；**默认不自动推送通知**；用户再次说「今日复习」并选集后才抽出已到点卡；若跨日未练则按逾期处理 | 到点提醒为可选后续例程，非默认行为 |
| A21 | P0 | 继续已到点题目 | 用户说「继续」时，在已选集上下文中接着抽出已到点题目 | 与「今日复习」共用选集与 due 规则 |

## 4. FSRS 服务

| 编号 | 优先级 | 功能 | 详细行为 | 验收标准 |
|---|---|---|---|---|
| S01 | P0 | 问答卡状态 | 支持新卡、学习中、复习、重学和暂停状态 | 每次状态转换有日志可追溯 |
| S02 | P0 | 调度计算 | 使用问答卡当前记忆状态、实际复习时间和用户评分计算间隔 | Grok Bot 的评价结果不直接作为评分输入 |
| S03 | P0 | 未学习队列 | 按日界线查询今日未学习与逾期问答卡 | Asia/Shanghai 日期切换准确；失效、作废、暂停或暂缓的问答卡不进入队列 |
| S04 | P0 | 目标保留率 | 用户设置目标保留率，默认值可配置 | 修改后影响后续调度，并记录配置变更 |
| S05 | P1 | 每日限制 | 设置每日新卡上限和复习上限 | 超出部分顺延，不丢失到期状态 |
| S06 | P1 | 最大间隔 | 控制问答卡最长复习间隔 | 调度结果不超过设置值 |
| S07 | P1 | 逾期处理 | 使用真实间隔计算，不因中断而清空历史 | 用户返回后能从原状态继续 |
| S08 | P1 | 复习排序 | 支持按到期、可提取性或逾期程度排序 | 排序只影响队列，不修改复习状态 |
| S09 | P2 | 参数优化 | 复习样本足够后可用专门优化器更新 FSRS 参数 | 参数带版本并可回滚；不由 Grok Bot 猜测 |
| S10 | P1 | 负载预测 | 按当前问答卡和设置估算未来复习量 | 明确标注为预测而非承诺 |

## 5. 理解练习组件：概括对照与理解问答

对比：本节（概括对照 / 理解问答）=「先写再对照」练习册；§6 讲解追问（原费曼）= 用户主动讲清楚 + 学生式追问。两者同属导航大类「理解练习」，都不进日常 FSRS 间隔；讲解追问不从今日复习自动进入。无用户口令「深度练习」。

| 编号 | 优先级 | 功能 | 详细行为 | 验收标准 |
|---|---|---|---|---|
| O01 | P0 | 概括对照（先写） | 给出内容卡片范围，要求用户用自己的话概括（用户口令「概括对照」） | 提交前不展示参考摘要；MVP：`practice.py summary-start` |
| O02 | P0 | 概括对照（对照） | 提交后并排展示用户摘要、参考摘要和原文摘录 | 反馈区分遗漏、误解和表达差异；MVP 为规则 stub，质量可经 Flash enrich |
| O03 | P0 | 理解问答作答 | 逐题输入完整回答（用户口令「理解问答」） | 参考思路在提交前保持隐藏；MVP：`practice.py open-*` |
| O04 | P0 | 多维反馈 | Grok Bot 按概念准确性、因果、证据、迁移和边界评价 | 不以单一总分代替文字反馈 |
| O05 | P1 | 修订回答 | 用户根据反馈再次作答 | 保存前后版本和仍未解决的问题 |
| O06 | P1 | 独立排期 | 用户可选择立即练习、设置下次日期或不安排 | 不把 AI 评价直接写入 FSRS 问答卡状态，也不自动占用问答卡复习会话 |

## 6. 理解练习组件：讲解追问（原费曼）

对比：讲解追问 = 用户主动讲清楚 + 学生式追问与修订；§5 = 概括对照 / 理解问答「先写再对照」。同属「理解练习」，都不进日常 FSRS 间隔；讲解追问不从今日复习自动进入。

| 编号 | 优先级 | 功能 | 详细行为 | 验收标准 |
|---|---|---|---|---|
| F01 | P0 | 发起方式 | 用户口令「讲解追问」，从卡片集、内容卡片或概念主动开始 | 未经用户选择不得自动进入；**MVP** 须显式 `--set`/`--content`/`--note`；复习后建议与「稍后安排」队列为**目标能力，MVP 未做** |
| F02 | P0 | 首次解释 | 用户先用自己的话解释，Grok Bot 不提前提供标准解释 | 首次解释按原样保存 |
| F03 | P0 | 学生模式追问 | Grok Bot 以学生身份追问术语、因果、例子、边界和反例 | 每轮只围绕当前缺口提问，等待用户回答 |
| F04 | P0 | 解释诊断 | 对照原文指出错误、模糊处、跳步和缺失联系 | 每条诊断附来源或标记为推断 |
| F05 | P0 | 再次解释 | 用户吸收反馈后重新讲一遍 | 保存首次与修订版本，可比较变化 |
| F06 | P1 | 薄弱点提取 | 从对话提取尚未掌握的概念和关系 | 薄弱点不自动等同于“遗忘卡片” |
| F07 | P0 | 补充问答卡草稿 | 用户选择“生成补充问答卡”后，Grok Bot 才针对薄弱点生成草稿 | 不默认生成；用户再次确认后才发布并初始化独立调度 |
| F08 | P1 | 练习结束条件 | 用户结束、连续解释完整或达到轮次上限时结束 | 结束时给出未解决问题；下次练习日期由用户决定是否设置 |
| F09 | P1 | 历史对比 | 查看同一概念历次解释和问题变化 | 能追踪哪些缺口已解决、哪些仍存在 |
| F10 | P1 | 理解练习队列 | 单独展示用户已安排的讲解追问、理解问答和概括对照任务 | 与 FSRS 分开；**MVP 简化**：无独立 DeepPracticeSchedule 表，今日总览汇总 open_questions / content_summaries / feynman_sessions 状态 |
| F11 | P1 | 建议处理 | 对系统提出的讲解追问建议执行现在开始、稍后安排或忽略 | 忽略不影响 FSRS；**MVP 未做**建议流 |

## 7. 统计组件与基础服务

| 编号 | 优先级 | 功能 | 详细行为 | 验收标准 |
|---|---|---|---|---|
| D01 | P0 | 持久化 | 保存卡片集、内容卡片、知识笔记、问答卡、回答、调度、对话和配置 | 重启或更换会话后完整恢复 |
| D02 | P0 | 审计日志 | 记录生成、确认、评分、撤销、编辑和调度变更 | 可追踪问答卡状态为何变化 |
| D03 | P0 | 备份恢复 | 完整导出并恢复用户学习数据 | 恢复后 ID、关系和复习历史保持一致 |
| D04 | P1 | 记忆统计 | 展示复习量、耗时、评分分布、遗忘率和实际保留率 | 统计口径和时间范围可见 |
| D05 | P1 | 理解统计 | 展示理解问答完成、讲解追问、未解决缺口和修订次数 | 与记忆统计分开；**MVP 未做**独立统计面板 |
| D06 | P1 | 提醒 | 分别提醒未学习问答卡与已安排的理解练习；**MVP 无通知服务、默认不推送** | 产品能力可选；到点提醒非默认 |
| D07 | P0 | 数据隔离 | 每个用户只能访问自己的材料和学习记录 | 服务端校验资源归属 |
| D08 | P0 | 密钥保护 | Grok API 密钥只保存在服务端 | 浏览器和导出文件不包含密钥 |
| D09 | P1 | 调用监控 | 记录 Grok Bot 请求状态、延迟、模型版本和消耗 | 日志不保存不必要的敏感原文 |
| D10 | P1 | 降级运行 | Grok Bot 不可用时仍可查看内容卡片、手动创建问答卡和完成既有复习 | 调度和本地数据不依赖 AI 在线状态 |
